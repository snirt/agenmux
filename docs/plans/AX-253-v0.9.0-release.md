## Implementation and verification plan

1. Compare the candidate with v0.8.7 and `origin/poc/rex-multiplexer`. Account for removed tests and fixtures, preserve shipped Pi rules and daemon/boundary coverage, and distinguish deliberately deferred prototypes from missing release behavior.
2. Review Rex setup, lifecycle, layout, navigation, clipboard, reload and beta limitations against implementation. Correct release notes and documentation where needed.
3. Run `cargo test --locked` and `bash tests/run.sh` under explicit Bash. Exercise real tmux and a foreground Rex server with explicit scratch socket, state directory and config, clearing inherited backend context. Never target the user's main Rex server or daemon; signal only verified test-owned children.
4. Update release notes, then run `/bin/bash -c 'make minor-bump'` once. If tests fail after version files change, fix and rerun suites without bumping again. Check manifest/lock/notes agreement, unused target tag and PR readiness.
5. Review exact diff/status and scan changed/new files for credentials and private data. Record sanitized verification outcomes here, not raw captures or local paths.
6. Report approval gates: commit/push/PR, then merge/publication. After approved publication, verify tag/commit, four archives, checksums, packaged binary and site deployment.
